# Private Render preview: My Learning Year and mathematical writing

Prepared for the **existing** service `srv-dbaeu33ncjis73dagjt0`, `openpath-pr55-preview`, at `https://openpath-pr55-preview.onrender.com`. This change does not call Render, deploy, merge, change service settings or provision a database. The URL will continue running its currently selected revision until the owner explicitly authorizes a deployment.

## What was ported

The working reference is `preview/render-pr55` at `453cebb5f7c21ea9be7c2db83ba354dd28eba0d5`. Its `deploy/preview/Dockerfile`, startup and password-gated Node frontend/Django proxy are ported onto the v3 baseline `af0aef182d2ec4e6fb0b1de9bc94dab034cbf411`.

Changes needed for v3:

- Keep Render's existing `./deploy/preview/Dockerfile` path and repository-root build context.
- Build the existing integrated English, Mathematics, Writing, My Learning Year and content-review entries; retain the Tamil entry point. No test-review fixture is enabled.
- Disable preview asset caching so a new feature branch is visible without manual phone-cache clearing.
- Serve `/year/` and `/review/` from their own `index.html`, including trailing-slash redirects and refreshes. Existing writing URL hashes and query parameters resume the same account-backed lesson.
- Serve ONNX `.mjs` as JavaScript and `.wasm` as `application/wasm`; allow same-origin WebAssembly compilation in the private preview's CSP. The actual local recognizer is browser-tested through this gateway.
- Run Gunicorn on loopback and the gated frontend on Render's `PORT`. Supervise both processes; a child exit stops the container. `/healthz` returns 200 only when Django and a database query succeed; otherwise 503. It reveals no account information.
- Use a non-root runtime user. Normalize source permissions so restrictive cloud checkout permissions cannot stop startup. Pin base-image digests, existing dependency locks, Gunicorn and its packaging dependency.

`backend/config/preview.py` and `preview_urls.py` are preview-only. The ordinary Django settings, learning screens, curriculum, input contract, estimators and mastery rules are unchanged.

## Environment variables and data isolation

| Variable | Requirement |
| --- | --- |
| `DEMO_PASSWORD` **or** `DEMO_PASSWORD_HASH` | Required for optional account-access gate (not student demo entry). Password at least 8 characters; preferably a long unique password. Hash format is generated by the existing `frontend/scripts/demo-hash-password.mjs`. Never reuse production credentials. |
| `DEMO_SESSION_SECRET` | Required, random, at least 32 characters. Preview-only signing key. |
| `DJANGO_SECRET_KEY` | Required, independent preview-only random key; use at least 50 characters. |
| `DEMO_SESSION_HOURS` | Optional; default 168. |
| `PREVIEW_DATABASE_URL` | Optional. Only an **existing dedicated synthetic preview PostgreSQL** database. Leave unset for isolated container-local SQLite. Never bind a production URL. |
| `PREVIEW_ORIGIN` | Usually unset: automatically `https://${RENDER_EXTERNAL_HOSTNAME}`. Set only for a local loopback test; the existing Render hostname needs no override. |
| `RENDER_EXTERNAL_HOSTNAME`, `PORT` | Supplied by Render. |
| `OPENPATH_PREVIEW_DATA_DIR` | Optional local SQLite directory; default `/app/preview-data`, writable by the runtime user. |
| `DEMO_ALLOW_HTTP=1` | **Local tests only. Do not set on Render.** Default requires secure preview/account cookies and uses HTTPS at the proxy. |

No paid API key, SMTP credential, production database, production signing key or real learner data is required. Startup removes ordinary `DATABASE_URL` and common model-key variables; settings only use `PREVIEW_DATABASE_URL` or synthetic SQLite. Both evaluators are forced disabled. Mail uses Django's dummy backend. The Docker context excludes environment files, existing databases, Git metadata, virtual environments, dependency caches and key files. Build-only trust certificates, if needed by the development network, are mounted as secrets and absent from the runtime image.

The older service may still have `DATABASE_URL` from its PR55 preview database. This change deliberately **does not use it**. If the owner wants to retain those synthetic fixtures across redeployments, explicitly bind that verified **preview-only** database to `PREVIEW_DATABASE_URL` before the authorized deployment. No existing database is migrated or touched by this task.

SQLite data survives a restart of the same container, as tested. It is **ephemeral across Render replacements, redeployments or free-instance lifecycle events**. Use an existing dedicated synthetic preview PostgreSQL database if persistent review fixtures are needed; this task creates none. Gate logout does not delete server records. Raw `DEMO_PASSWORD` is salted at startup, so owner account-access sessions require logging into that gate again after restart; account records remain in the configured database. Student-demo gateway sessions use a separate versioned key derived from `DEMO_SESSION_SECRET` and survive a same-container restart for their two-hour lifetime, as do their separate Django sessions.

## Reproduce locally

From the repository root:

```bash
docker build -f deploy/preview/Dockerfile -t openpath-preview:local .
```

Create a local-only environment file outside the checkout, mode 0600, containing:

```dotenv
DEMO_PASSWORD=synthetic-preview-test-pass
DEMO_SESSION_SECRET=<new random preview-only value of at least 32 characters>
DJANGO_SECRET_KEY=<a different random preview-only value of at least 50 characters>
DEMO_ALLOW_HTTP=1
PREVIEW_ORIGIN=http://127.0.0.1:4690
```

Then run:

```bash
docker run -d --name openpath-preview -p 127.0.0.1:4690:10000 \
  --env-file /tmp/openpath-preview.env openpath-preview:local
curl --fail http://127.0.0.1:4690/healthz
cd frontend
npm ci
CHROMIUM_PATH=/usr/bin/chromium E2E_URL=http://127.0.0.1:4690 \
  PREVIEW_PASSWORD=synthetic-preview-test-pass node --import tsx --test --test-concurrency=1 \
  scripts/preview-server.test.mjs scripts/demo-server.test.mjs \
  e2e/preview-container.test.mjs e2e/writing-year.test.mjs
```

Wait for `/healthz` to return 200 before tests. To verify persistence, restart **that same synthetic container**, wait for readiness, then run `PREVIEW_PHASE=resume` with the same browser command restricted to `e2e/preview-container.test.mjs`. Its fixture record is stored in `/tmp/openpath-preview-container-state.json`. Never run this synthetic fixture test against a production service.

The current cloud runner needs local Docker configuration in writable `/tmp`, proxy environment forwarding, a build-only proxy hostname mapping and its existing trusted CA. These are development-network prerequisites, **not Render settings**; TLS verification remains enabled:

```bash
preview_proxy_mapping="$(python -c 'import os,socket,urllib.parse; h=urllib.parse.urlsplit(os.environ["HTTPS_PROXY"]).hostname; print(h+":"+socket.gethostbyname(h))')"
DOCKER_CONFIG=/tmp/openpath-docker docker build --network=host \
  --add-host "$preview_proxy_mapping" \
  --build-arg HTTPS_PROXY --build-arg HTTP_PROXY --build-arg NO_PROXY \
  --secret id=build_ca,src="$NODE_EXTRA_CA_CERTS" \
  -f deploy/preview/Dockerfile -t openpath-preview:local .
```

No certificate, secret value or proxy credential is committed. The optional CA mount is absent on normal Render builds.

## Executed validation

The exact Dockerfile built successfully locally with the development-network flags above. The resulting image ran as UID 10001; migrations completed; Gunicorn and the password-gated frontend started; Docker health was `healthy` and public `/healthz` returned 200.

- 7 browser tests passed against the image: gate protection, all packaged entries, MIME/CSP, actual Django evidence/draft saving, normal My Learning Year navigation, division error/follow-up/teaching/correction, fractions, multiplication, real ONNX digit recognition, ambiguous mark confirmation, unavailable-model typed fallback and zero falsely verified skills. Browser widths include phone and desktop.
- 1 further browser test passed after a real container restart: same synthetic parent/learner, same evidence count and unfinished saved working.
- Full Django suite: 217 passed both on the host and inside the final image, including three preview readiness/isolation tests.
- Four frontend TypeScript configurations passed. The Docker build executed the actual integrated frontend and Tamil builds.
- 13 gateway tests passed, covering secure cookies, HTTPS forwarding, cross-origin login rejection and unhealthy backend behavior, plus existing password-gate regressions.

Initial local build attempts failed on the cloud Docker config directory permissions, CA trust and proxy DNS; these were diagnosed without bypassing TLS. The first non-root startup found restrictive source permissions; the Dockerfile now normalizes them. Passing results above are from the corrected image, not those failed attempts. A root-directory Django test invocation discovered zero tests and was not counted; the 217-test run was executed from `backend`.

The image also booted with Render-style HTTPS settings (no HTTP test switch); local trusted-proxy-header simulation verified HTTPS redirection and Secure/HttpOnly gate and Secure Django CSRF cookies. This was not a live Render TLS test.

The normal learning code and Node 24 research-fingerprint baseline are unchanged; that unrelated research suite was not rerun for this deployment-only change. No physical stylus/Android hardware or live Render deployment was tested. No Render service, resource, secret or setting was changed.
