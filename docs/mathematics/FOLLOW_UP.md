## Canonical adapter: implemented and tested, not wired into production

`packages/mathematics/src/canonical.ts` imports the existing `Composite`, `EvidenceEvent`, `Item`, `Provenance`, `Context`, `Ledger`, `indexContent`, `scoreCode` (in tests) and `leafView` contracts. It creates no learner model, policy, estimator, evidence ledger or profile store.

1. `preparePractice` binds a saved activity receipt to **the existing `Composite.learnerId`**. The host can supply its existing `ProfileEvent.id` as that identity, as the integration test does. Ledger, activity and identity must agree. Unregistered MATH competencies fail closed; no English alias is created.
2. Items are regenerated from family/version/seed and checked against the activity's competency, program version and item ID. Native correctness is recomputed from the original response, not trusted from the activity's `correct` flag. Unsupported symbolic answers are not turned into invented wrong binary evidence.
3. The result is a `math-ledger-practice@1` packet: a **provisional native CodeItem**, a native `EvidenceEvent` with `use:practice`, and a required sidecar preserving raw response, original generated item/seed/parameters/provenance, journey/program/version, hint count, solution exposure and duration. Sidecars are item/receipt transport artifacts, not a parallel evidence ledger.
4. Exact numeric/polynomial/set representations are encoded in a versioned `typed:math-canonical@1` transport format so the unchanged code scorer accepts mathematically equivalent answers. Choice letters are mapped to the selected semantic option for coordinate questions; shuffled positions do not create conflicting item versions. The learner-facing original prompt/options/format remain in the sidecar. This format is a **practice transport**, not a validated exam format or difficulty model.
5. Native identity is based on family/version, actual question stem and semantic answer, not seed or unused parameters. Identical questions therefore enter the existing ledger as repeats, even across school/GRE journeys. Different variants share one native family identity. A new wording or seed is never proof of independent understanding.
6. `contentWithPractice` validates an immutable native content snapshot with the existing indexer and rejects eligibility upgrades or conflicting item versions. All items have `evidence_status:provisional`. Mandatory legacy `a/b` fields are transport-only placeholders using the host prior; **they are not calibrated mathematics parameters** and must never be used to promote these items into assessments. The legacy lexical `GeneratedFrom.word` field is not misused for mathematics; full original provenance is preserved in the sidecar.
7. Host-provided canonical presentation/hint/intervention references are checked against existing ledger events. A count of hints is not enough to invent event IDs or timestamps. Without real host lineage, provenance stays absent/unknown, never fabricated as independent. The sidecar still retains hint and solution facts.
8. The host installs the item snapshot, persists its sidecar and native event through its **existing `LearnerStore`**, then applies/rebuilds its existing ledger. The integration test uses the real `MemoryStore`, `Ledger.apply` and `Ledger.rebuild`. The existing provisional/assistance gate holds the responses and leaves all competency nodes unchanged. Native receipt IDs are stable for retry deduplication; production must make artifact + event persistence atomic/idempotent.
9. `sharedProfile` reads the existing `leafView` verification/retention/stage and evidence trail without new mastery thresholds. Missing registration or no admissible evidence renders unavailable; program completion is not consulted.

**Registration limitation:** production's `indexFramework` still requires EN hierarchy. Tests extend the loaded index **in memory as a named host-registration fixture**, using unchanged policy solely to exercise transport/eligibility. This is not a production MATH framework, reviewed mathematics policy, or a bypass shipped into the app. A shared subject-neutral registration seam is still required before production wiring. Existing native/profile contracts are reused, but no unsupported claim of production integration is made.

**Persistence limitation:** the adapter prepares packets, not a live account endpoint or multi-store transaction coordinator. The host must implement atomic artifact/content/event persistence, existing authenticated learner ownership checks, conflict handling and version retention. Encoded native item IDs currently contain the collision-free semantic key; check backend/API identifier length/encoding constraints before wiring, or introduce a versioned content-addressed key with collision checking. Do not truncate keys.

## Required school → GRE integration scenario

School resumes at independent practice (43% activities); GRE resumes at guided practice (29%). Separate versioned program keys survive JSON storage/reload. Native ledger observations distinguish fresh/variant/repeat across journeys. Every generated response is held, competency nodes remain unchanged, no verified evidence appears and exam readiness stays `not-estimated`. A ledger rebuild from the existing store reproduces the same profile and decisions.

Completion counts distinct completed **activity IDs**. A small defensive fix deduplicates repeated completion IDs so a replay/import cannot inflate the percentage. No lesson stage, sequence or curriculum version is changed.

None is educator reviewed.** All concept stages restate objectives; all application/transfer stages reuse the same family template. The worked solutions provide a limited worked-method explanation, not a sequenced conceptual lesson.

Concrete repetition defect: percent, geometry and probability each yield **3,263 fingerprints but only 740 stems** in this sample. The canonical codec now uses actual stem/semantic answer and folds these duplicates for shared-ledger history. The unchanged v1 standalone generator/UI batch still uses parameter fingerprints, so it may reissue these disguised duplicates; that limitation remains visible. Correcting generator novelty/difficulty and upgrading lesson content should be versioned follow-up work, not an unreviewed rewrite of the accepted foundation. Same-family variants never become independent evidence here.

**Exam readiness, official timed tests and scoring remain disabled.** Official-current format/syllabus verification is still outstanding. No claim is made that these samples model real JEE/GRE difficulty or establish effectiveness with children.
