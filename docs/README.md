# OpenPath documentation

> **Current direction (12 Oct 2026):** the first product is an adaptive
> English-learning app for ages 10–15. Start with
> [`english/README.md`](english/README.md). The documents below set out the
> platform principles, which still apply. Their V1 plan and M1 are paused or
> superseded.

**Starting a work session?** Read [`STATUS.md`](STATUS.md) first. It says what is in flight and what is next.

Suggested reading order for the product owner:

1. [`PRODUCT_VISION.md`](PRODUCT_VISION.md): what OpenPath is, in my words, for you to check.
2. [`REPOSITORY_AUDIT.md`](REPOSITORY_AUDIT.md): what the code does today, what is missing, and what is too tied to shopping.
3. [`PLATFORM_ARCHITECTURE.md`](PLATFORM_ARCHITECTURE.md): the proposed modules and how they connect.
4. [`CAPABILITY_MODEL.md`](CAPABILITY_MODEL.md): the capability profile, evidence, goals, pathways and recommendations, with examples.
5. [`PRODUCT_MODULES.md`](PRODUCT_MODULES.md): products versus experiences, and the second test experience.
6. [`V1_IMPLEMENTATION_PLAN.md`](V1_IMPLEMENTATION_PLAN.md): the smallest credible V1, its milestones, and what can wait.
7. [`DECISION_LOG.md`](DECISION_LOG.md): what is agreed, what I recommend, and what is still open.

Milestone scopes, each approved before it is built:

- [`milestones/M1_CAPABILITY_REGISTRY.md`](milestones/M1_CAPABILITY_REGISTRY.md): capability registry and observable profile (awaiting approval)

[`ARCHITECTURE.md`](ARCHITECTURE.md) is the original design record of the apple-shopping prototype. It is superseded for platform matters.

Every document uses the same labels:

| Label | Meaning |
|---|---|
| **Agreed** | You stated this as a requirement. |
| **Recommended** | My proposal. It waits for your approval. |
| **Future** | Room is kept for it. It is not approved. |
| **Open** | Needs your decision. |
