# Exact-number reasoning engine (`packages/learning/src/core/number/`)

Reusable engine for working on integers, fractions (tight `3/4` or spaced), mixed numbers, decimals, percentages, ratios and two-part proportions (one unknown, linear), powers (integer, negative, exact fractional), factors, HCF/LCM, exact square roots, and units (length, mass, volume, time, money). BigInt rationals only; no floating point. No family-specific answer logic: a line is judged by its exact value.

API (the existing unified core): `assessWorking(problem, lines, opts?)` and `verifyWorkingStep(problem, from, to)` in `core/working-assessment.ts` route exact-number problems here; the result keeps the advisory contract (outcomes verified / invalid / ambiguous / unsupported / incomplete; marking stays with the educator) and adds `number`: candidate misconceptions, final-answer form, and skill demonstration. Algebraic equations in x still go to the algebra core. Direct API: `assessNumberWorking`, `verifyNumberStep`, `readProblem`, `checkForm` (`core/number/index.ts`).

Behaviour: any line sequence is accepted if each line equals the previous one in exact value (multi-operation steps included); a chain `a = b = c` checks every equality; a true equality about part of the working (`12 = 2^2 × 3`) is a valid fact; the first line whose value differs is the first incorrect transformation; constraints (division by zero, incompatible units, negative HCF…) make a line invalid; a required form (`simplest form`, `as a percent`, `in cm`, `as a product of primes`) or an unfinished last line gives `incomplete`, not `invalid`.

Error identification (`errors.ts`): single-fault replay. One operation of the previous line is rewritten as a known misconception would (tops and bottoms added, no inversion on division, indices multiplied, percent as whole number, order of operations, units ignored, HCF/LCM swapped, sign and decimal-place slips, ratio inverted, …), evaluated exactly, and kept if it reproduces the student's line. Output is a list of candidates, never a diagnosis; no match means no claim.

Skills (`skills.ts`) are detected from the shape of the working, independent of correctness: common denominator, equivalent fraction, reduce fraction, prime factorisation, unit conversion, index laws, percent conversion, cross-multiplication, equal-ratio scaling. `skills.status` is `demonstrated`, `not-demonstrated` (answer may still be right) or `n/a`.

Limits: two-part proportions only; one unknown, linear; no irrational numbers (refused as unsupported); exponents up to 400 and numbers up to ~6000 digits; natural-language problems only for the forms in `readProblem` (HCF/LCM of, simplify, express as, convert to, as a percent/fraction/decimal/mixed number/product of primes); `a ÷ b(c)` style lines are reported `ambiguous`; error identification covers single-fault errors only; a line with no recognised cause just reports invalid. Skill detection is structural and can miss unusual layouts (reported as not demonstrated, never as wrong). Evaluated on hand-written cases only, not on real student working.
