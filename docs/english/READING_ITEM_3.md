# Item 3: one long literary text, read in parts

`Read a story in parts` opens from the existing Reading map. *The Space on the Board* is an original 850-word story in four parts. Each part has one question; two whole-text questions connect title/theme development and Nila's changing role. This is one bounded activity, not a level, age/class label, validated ability estimate, or mastery award.

## Editorial dependency check

The whole-title options share one premise at a time. With only the opening, both the correct option and the family-notices option survive: the later use is not known. With only the ending, both the correct option and the unfinished-board option survive: the initial reason for the space is not known. The opening's measured card and ending's relocated card plus a rider's contribution support the complete transition.

The character options likewise share endpoints. The opening supports Nila organising the board but cannot decide between later independent contributions and Ravi approving posts. The ending supports independent contributions but cannot decide whether Nila originally organised it or left decisions to Ravi. Early writing/layout plus late reachable materials and an independently posted notice support the full change. The story does not state its moral. This is an editorial ablation check, not an empirical learner study.

The six correct options occupy positions 1/2/3 twice each; none is uniquely longest. All sentence indices are checked against the runtime splitter. Whole-text accepted evidence sets require early and late parts. Sentence evidence is checked against bounded authored sets, so plausible support outside those sets is not automatically accepted.

## Persistence and honest results

A dedicated profile-specific local story checkpoint contains the story signature, current part/question, unlocked or locked answer, cross-part evidence, and submitted answers. It does not write ordinary Reading capability/history/exposure or change existing causal/inference journeys. All changes save before the next screen opens. Storage failure hides the new screen until retry; a changed record in another tab refuses to overwrite newer work. Invalid or content-drifted records are retained and refused, not silently reset. An explicit Close and archive action first saves an unchanged copy under a separate device key, then closes the active record without scoring it. The learner can begin again with an explicit repeat-reading notice, never an unseen/fresh-assessment claim.

Previously opened parts remain available without highlighting or feedback. Rereading preserves the question draft and locked answer. All explanations and answer/evidence results stay hidden until all six submissions. Answer correctness and evidence completeness remain separate. A completed checkpoint reopens the same result; no restart button or duplicate award exists. This local activity is not server-synced, fresh-pool placement, or a security boundary against browser storage editing.
