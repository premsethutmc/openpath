# The hosted server for a real learner (family-pilot@1)

The demo's device mode (DEVICE_MODE.md) keeps a record in one browser. A real learner needs the record kept: on a server,
in a database, reachable from any device, and readable (with the parent's permission) to improve the product. The server
already existed and is tested (accounts, learners, records, server-side grading); what was missing was somewhere to run it
with a database that lasts.

## What it is

One private site, one origin:

- the site password first (nothing is served before it), as on the demo;
- then OpenPath's own parent account (email and password), and the learners under it;
- the welcome screen with the English and Maths tiles; a learner can be added from either;
- records in the owner's own PostgreSQL database (Neon's free plan), reached only over an encrypted connection.

Files: `deploy/pilot/Dockerfile`, `deploy/pilot/start.sh`, `backend/config/pilot.py`, `render.pilot.yaml`. It is the preview
deployment (`deploy/preview`, synthetic data only) with one difference that matters: the preview ignores `DATABASE_URL` and
falls back to a throw-away file; the pilot refuses to start without its PostgreSQL database, so a real record can never land
in a file the next deploy discards.

## Setting it up (owner)

1. Neon: create a free project (region Singapore), copy its connection string.
2. Render: the service `openpath-family` (free, Docker, Singapore, branch `main`, deploys only when asked). In its
   Environment set `DATABASE_URL` to the Neon string and `DEMO_PASSWORD` to a site password of your choosing. The two secrets
   (`DEMO_SESSION_SECRET`, `DJANGO_SECRET_KEY`) are generated by Render.
3. Deploy. `start.sh` applies the database migrations, checks the settings and the grader bundle, then starts.
4. Open the site, enter the site password, choose English, create the parent account, then open Maths and add the learner.

Neither the connection string nor the passwords are committed, logged, or sent through chat.

## What to expect

| | |
|---|---|
| First visit after a quiet spell | Slow: a free Render service sleeps after about 15 minutes without visitors and takes about a minute to wake; a Neon database also wakes on first use |
| Progress | Kept in the database; the same on any device after signing in |
| Grading | The server's recorded decision is what is shown (mode `shadow`, as approved for the preview) |
| Forgotten account password | There is no mail service, so no reset link can be sent. Keep the password safe; it can be reset by hand in the database if needed |
| Backups | Neon's free plan is not a backup. The parent can export a learner's record (Me → export in English; `/api/pupils/<id>/export/`). A scheduled backup is not built |
| Who can read a record | The parent. A developer only if the parent turns on sharing for diagnostics for that learner (every look is logged) |
| Written answers | Saved; marked only by an educator account, which the pilot does not have yet |

## Checked

- `backend/config/test_pilot_settings.py` (3): no database → refuses to start; debug → refuses; with a database → PostgreSQL,
  encryption required whatever the address says, model services off, server clock.
- By hand, in a headless browser against the same one-origin server pair (the gate server and Django) with a test database:
  site password → welcome tiles → English → create parent account → Maths → add learner → Board CISCE, Grade 5 → Start
  learning (62 skills) → answer → stored on the server with the server's decision "correct".
- NOT checked here: the Docker image build and the connection to Neon. This environment has no Docker daemon and no database
  driver; the image is the preview's, which has built and run on Render before. The first deploy is the test: `start.sh`
  stops with a clear message if anything is missing.

## Before a child uses it

- The owner holds the parent account and decides what name is shown (a first name or nickname is enough).
- This is an early version: lessons and questions are machine-checked, not reviewed by a teacher.
- Free plans change. If Render or Neon change theirs, the record should be exported first.

## Signing in once (one-account@1)

- Maths has its own "Create an account" on its sign-in screen; a parent is never sent to another app to register.
- A parent's sign-in lasts 180 days on a device; the site password is asked once a year per device.

## For parents (parent-view@1) and keeping progress safe (keep-safe@1)

- "For parents" on the Maths home: questions this week, right at the first try, days worked, lessons opened, a bar for
  each of the last seven days, and the skills worked on in the last 14 days grouped as could use your help / going
  well / also worked on. All are counts from the learner's record; nothing is estimated.
- A name-only learner's parent can add an email and password there ("Keep this progress safe"). The same records then
  open on any device, and the browser's own key is removed. There is no reset-by-email on this site yet.
- An email account's parent can download a copy of the learner's record from the same page.

## Timing and the competency profile (timing@1, competency-profile@1)

- Each answer now carries about how long the question was on screen (`ms`; the clock stops while the page is hidden, and
  more than ten minutes is treated as a pause and not kept). It is never part of how an answer counts.
- The parents' page has Week / Month / Year. For each topic it shows questions, right at the first try, answered without
  help, and pace; and four findings: quickest, most accurate, most practised, stuck on.
- Measures, not predictions: "quicker" compares the learner with their own usual pace (the middle of their topic paces),
  never with other children; a measure appears only after five answers. Timing exists only from 13 Nov 2026.

## Opening at once (instant-open@1) and staying in (stay-in@1)

- The Maths page carries its own first screen (plain HTML and CSS), so something is on screen before any script runs.
- The family image builds Maths with `--shell-cache`: a service worker at `/year/sw.js` keeps the app's own files on the
  phone, answers from that copy at once (also while the server is asleep), and fetches newer files for next time. It
  never handles `/api/` or anything outside `/year/`. If a newer app arrives while the old one is starting and nothing
  has been touched, the page reloads itself once.
- While the server cannot be reached the opening screen stays, says the first open can take up to a minute, and asks
  again every three seconds for two minutes. If the site password has run out, the visitor is sent to the password page.
- The site password's sessions now survive a restart (the salt comes from the session secret). Before, every restart,
  and so every wake from sleep, asked for the site password again.

## Question wording (kid-say@1)

In the child build every generated question is shown as one short ask (`packages/learning/src/kid-say.ts`). Only the
wording and the answer box change; the question, its answer and the marking do not. Rules: one ask, with typing rules
moved into the box (₹ before it, a unit after it, separate m and cm boxes, numbers to tap into order, a letter to
tap); a picture only where the maths is visual, and the sentence never does the picture's work; a calculation stays a
calculation. About 50 of the wordiest Class 5 families have their own rewrite; the rest follow the general rules.
`kid-say.test.ts` checks every Class 5 family: no typing instructions left, no number that the question did not give,
and every tap, order and two-box answer rebuilds an answer the existing marking accepts. Test and review builds keep
the full wording.

## Speed of saves (grader-serve@1, 16 Nov 2026)

- **The grader is kept running.** Checking one answer used to start a program and read the whole 15 MB grader each time
  (about 0.8 s on a development machine, more on the free server). The same bundle is now started once with `--serve` and
  asked one line at a time: about 1 ms an answer after the first. The decisions come from the same code; a test holds the
  kept grader's replies against one-shot runs. Any trouble (no reply in time, an unexpected reply, a dead process) falls back
  to a one-shot run. It is stopped after 1200 quiet seconds (`OPENPATH_GRADER_IDLE`; 120 at first, which stopped it during any lesson longer than
  two minutes, so the next answer paid the start again: 13 s measured on the family site on 16 Nov 2026, against 25 to 77 ms
  for the answers after it). grader-warm@1 starts it in the background when a learner's mathematics is opened, so the start
  is spent while a lesson is read; a grader just started is allowed `OPENPATH_GRADER_START` seconds (30). It is and restarted every 300 answers
  (`OPENPATH_GRADER_RECYCLE`). It holds about 300 MB while it runs, the same as one one-shot run at its peak, and the two
  are never in memory together. `OPENPATH_GRADER_SERVE=off` returns to a one-shot run for every answer.
- **Database connections are reused** for up to a minute and checked before each request (`CONN_MAX_AGE = 60`,
  `CONN_HEALTH_CHECKS`), so the saves of one sitting do not each open a new encrypted connection.
- Not measured on the live server (the free plan gives no timings). Open: the size of the app itself (14.8 MB of code,
  2.9 MB to download) and the server's small processor.

## The first answer after opening (grader-warm@1, 17 Nov 2026)

Measured on the family site: the first answer after the grader has stopped takes 10 to 13 s (the grader starting on 0.15 of
a CPU); later ones 25 to 130 ms. The grader is now started in the background when a learner's mathematics ledger is read (at
most once in five minutes), so the start is spent while the lesson is read. Only that warm-up, which asks nothing, gives a
fresh grader longer to start (`OPENPATH_GRADER_START`, 30 s). An earlier version gave every fresh start that time: a slow
working check then held an answer for half a minute, and the Grade 10/12 browser journey timed out four times running.

## An answer that cannot be read (ask-first@1, 17 Nov 2026)

On the family site the owner wrote two answers the checker could not read, eight seconds apart, and the skill was paused for
two days with "this needs a person" (pause@1 counts unreadable answers that were sent; the checker reads a bare number, so
"7 birds", "seven" and "9-2" are all unreadable). In the child build an answer the app's own preview cannot read is no
longer sent: the child is shown how to write it ("Type just your final answer, for example 7") and tries again at once.
Nothing is recorded, so this can no longer pause a skill. Other builds are unchanged: the first unreadable answer is
recorded and asked about, as before.

plain-answer@1: "7 birds" for "How many birds…?" is read as 7 (`packages/learning/src/plain-answer.ts`): only when the answer is a
whole number and every word after it is a thing the question names; never a unit ("7 cm"), never another word.

Open: "seven" and "9-2"; whether pause@1 should ever apply to unreadable answers.


## Teaching dashboard (teaching-review@1)

`/review/#teaching` lists every story lesson and help card, by class (Class 5 first), as the child sees it: a lesson
can be played there. Each shows where it came from (written by hand, or made by rule from the skill's lesson) and is
approved, rejected or sent back in one step by an account with the educator role (`manage.py content_reviewer grant
<email> --role educator`). A decision applies to the version shown: when the lesson or card changes it returns to "To
review". Decisions are a record only; they do not yet hide anything from learners. The items and their hashes are in
`content/learning/teaching.v1.json` (generated: `node tools/regen.mjs`).

## Words and picture agree (picture-words@1)

Where a question's words point at a picture ("the number cards in the picture") and the family draws a row of things
as a table with no real headings, the row is drawn as cards (`pictured` in `family-kit.ts`, `as: "tiles"` in
`Figure.tsx`), in the question and in its lesson. A table with real headings (a bill, a price list) stays a table.
`frontend/src/year/picture-words.test.ts` checks every family: words that point at a picture have one, and cards are
never drawn as a table of data.

The owner reviews teaching without a database grant when their account's email is in `OPENPATH_OWNER_EMAILS`.

## Money as coins (money-say@1, money-piles@1)

A bare sum of money (`₹7.55 − ₹3.15 = ?`, families `acmoneyadd`, `agrupee` and any other that prints that shape) is a
decimal calculation to a child who has not met decimals. By rule (`moneySum` in `kid-say.ts`) the child is told what
happens to the money in rupees and paise ("You have 7 rupees and 55 paise. You pay 3 rupees and 15 paise."), sees the
coins (`money-piles.ts`, `MoneyPiles.tsx`) and answers in two boxes, rupees and paise, which are joined into the
decimal the marking wants. Taking away, the child pays by tapping coins; when the paise are too few, one rupee is
changed into 100 paise. Adding, 100 paise are changed into ₹1. The piles are built so the amount can always be paid
exactly; the picture never states the answer. In a test the coins are shown but cannot be worked with.

`child-view@1`: the review page's "Try them" box shows the question as the child is asked it (their words, picture and
answer boxes), with the written form underneath.

money-say@2 (every money question, by rule in `general`): where a question wants paise in its answer, the child
answers in the rupees and paise boxes; wherever paise come into a question, an amount is said in its two parts
(₹3.15 → 3 rupees and 15 paise) and "1 rupee is 100 paise." is kept under it. This covers paise to rupees, rupees to
paise, multiplying and sharing an amount, and bills. Coins are drawn for adding and taking away only.

Open: coins for changing, sharing and multiplying an amount; fading from coins to columns to numbers alone.

## The picture beside a guess (guess-picture@1)

Before a "have a guess" only the question's own picture is shown. The lesson's teaching picture (a worked layout, such
as a pattern stacked so the ? sits under its answer) waits with the working (`frontend/src/year/guess-picture.ts`).
Before this, 108 lesson screens across 79 question types showed the teaching picture first. Tests check every lesson
with a guess, and that no question's own picture puts the ? under its answer.

## Fading help (support-ladder@1)

A question may name its aids, most help first (`aids` in `kid-say.ts`; a sum of money: the coins, then the amounts in
columns); after the last aid comes the bare question. `supportStep` (`packages/learning/src/support-ladder.ts`) picks
the step from the child's practice answers on that question type: two right in a row without help move up a step,
two wrong in a row move down. "Show me the coins" (the step below) is always offered; an answer given with it is
recorded as helped. A test is always bare. The rule is general: any question that names aids fades the same way.
Money sums are the first to name aids. A picture that is the question's data (a bill, a chart) is never an aid.

## Try it as a child (try-as-child@1)

`/year/#try` is the owner's view of the app as a child gets it: search any skill of any class and board, then open
the whole journey, the lesson alone, a practice question or a test question. It uses the child app's own screens
(`Module`, `Lesson`, `Ask`, `Feedback`) on a sandbox learner kept in the page's memory (`frontend/src/year/Try.tsx`):
no server call is made and no record is saved. The review page links to it.

## Lines of working beyond arithmetic (line-check@1)

`packages/learning/src/line-check.ts` reads a line of working as mathematics on the device: numbers with powers,
roots, π, sin/cos/tan, percentages; a definite integral (`∫ 0 to 3 (6 − 2x) dx`) and an antiderivative between limits
(`[6x − x²] 0 to 3`); an identity; an equation against the equation before it (same solutions); `∫ f dx = F + C` and
`d/dx (f) = g`. Each line must be worth the same as the line before; the first that is not is marked where it is.
Words, units and anything it cannot read are never called wrong. It does not use the question's stored steps, so any
valid route is accepted. The working box has keys for x, ², √, π, ∫, to, [ ], sin, cos, tan on questions beyond
arithmetic.

Open: 47 of 85 calculus question types (766 of 1,118 in all, many of them rightly one-step) hold two steps or fewer,
so "I'm stuck" has little to say on them; matrices, vectors and inequalities are not read; two unknowns only when the
equation is of first degree in the second.

## Finer steps inside a step (deepen@1)

`packages/learning/src/deepen.ts` reads the calculation in a step's own words and works it the way it is taught; each
line becomes a step of "I'm stuck" (`stepsHelp`, marked `finer`): whole-number × ÷ + − by place value; a definite
integral of powers of x (terms, antiderivative, upper limit, lower limit, difference); `∫ … dx` and `d/dx (…)` term by
term. Every line is checked true by the line checker in the tests, for every question type. 182 question types gain
finer steps.

Open: of the 745 question types with two steps or fewer (mid-range question), 679 still have two or fewer: about 100
are rightly one step (look, count, recall); the rest state a method without working it (chain rule, limits, matrices,
word problems) and need their steps written into the question type itself, which then needs its answer key
re-certified. Calculus: 43 of 85 types.

## Worked steps for calculus (deeper-calculus@1)

`packages/learning/src/deeper-calculus.ts` writes the working a calculus question's own steps leave out, per question
type, from the question's printed function (no question, answer or fingerprint changes): first principles, velocity
and marginal revenue, continuity with an unknown k, concavity, differentiability at a join, limits at infinity, the
chain and quotient rules, e^(ax) and log x, standard integrals, ∫ f(ax + b) dx, integration by parts (x times
e^(ax), sin, cos), partial derivatives, and any definite integral printed in the question (with |…| split where it
changes sign). The lines sit between the question's first step and its last in "I'm stuck". A shape it does not know
gets nothing. `deeper-calculus.test.ts` checks every calculation on about 660 questions with the line checker, and
that a working ending in a number ends at the keyed answer. Calculus types with two steps of help or fewer: 46 → 28.

The line checker now reads `log` both ways (natural in calculus, base ten in a logarithms chapter).

Open: the 28 remaining types (inverse trig, sin² and cos², products with log, limits by standard results, implicit
differentiation, series, several variables) and the variants of the handled types it does not read yet.

## Doing a step of help (step-ask@1)

In "I'm stuck", a step that ends in a result the line checker can judge ("Bring the power down: 8 × 4 = 32") is shown
with the result left out, and the learner enters it (`packages/learning/src/step-ask.ts`, `StepEntry` in
`StepCoach.tsx`). An entry is right when the line it completes is true, so an equal number or expression counts; a
right entry moves to the next step by itself. "Show me this step" stays. About a third of all steps of help (2,991 of
9,160 sampled, in 455 question types) can be entered; the rest are shown as before. The open help now takes the full
width, so the Check button keeps its size. The working box has ³ and ^ keys.

`stay-open@1` and `why@1` (StepCoach): a step that has been done stays on the page with what was done and the step
itself; the next step's "what to do" is shown straight away (no extra tap, nothing folds away); every step whose skill
has a card offers "Why? Show me the rule" (the other skill it leans on, or the question's own), and an opened rule
stays open while the next step uses the same one. Areas between a curve, the x-axis and two lines are worked from the
question's own limits (21 calculus types have worked steps).

## A picture to move, in practice (scene-aid@1)

A practice question can carry a scene (a picture the child moves) as an aid, so it fades like any other aid
(support-ladder@1) and is never shown in a test. First users: lakh, crore and million questions (`ajmill`, `ajmilr`)
show their own number with commas to move from one way of grouping to the other. Before this, only 18 of 1,118
question types had a movable picture in practice; the movable pictures of the story lessons were in lessons only.

## A worked example the learner does (lesson-interactions@1)

In the child build a lesson's worked example is no longer only read (`WorkedByYou.tsx`): the working is done one step
at a time with the stuck-help coach opened from the start (a step with a result is entered; "Show me this step" stays),
and then, where the question holds the wrong answers learners give, "Someone answered 37. What went wrong?" with the
reason that predicts that answer as the right choice (`packages/learning/src/lesson-interactions.ts`, from `guessOf`).
Nothing is recorded; none of it is in a test. Coverage (three questions sampled per type): 931 of 1,118 question
types get at least one of the two (910 spot-the-mistake, 490 with a step to enter); ICSE Class 5: 199 of 235 types,
and 59 of its 62 skills have a worked example. A result with a unit, ₹ or commas can now be entered (step-ask@1).

Tried and dropped: "What would you do first?" made from the kinds of step ("Add" against "Convert" is not a fair
choice). Not built: putting shuffled steps in order (some steps can fairly go in either order).

`scene-aid@2` (rounding): a rounding question in practice starts with its number line to move (`practiceScene` in
`scenes.ts`): the point starts on the number and is carried to the round number on each side with the steps counted
("Start at 557 · 3 forward · now at 560"); nothing is printed before it moves, and a nudge at the farther end counts
those steps and points to the other. Then the still number line, then the bare question (support-ladder@1).
`nudge@1`: commas name the group that is still the wrong size. Commas are dragged; their sliders are folded away.

`practice-tool@1` (`practiceScene` in `scenes.ts`): a question's own picture becomes a tool in practice by rule, not type
by type. A number line drawn with the starting number becomes a point to carry, the steps counted; the bar to shade, the
rectangle to build and the bars to read come from the lesson's converters. Tools are `quiet` (the goal is never
announced; the answer is still typed in its box), are offered only where the rule fits every drawn question of the type,
and never where their words or first readout hold the answer. First audit of Class 5 (235 types): 141 words and a box,
64 a still picture, 22 something to do, 8 movable in the lesson only.

`teaching-cards@1`: how a group of types is taught is decided per group, from the mistakes we store for it, then applied
by rule. Three cards so far.
- Rounding (`roundTool`): any question asking for one whole number rounded to ten, hundred or thousand, read from its own
  words and kept only when that rounding gives the verified answer. `decide@1` (`first` on a scene): the learner first
  picks the two round numbers the number sits between (the line is hidden until then), then carries the point to each.
  Estimates (two numbers) and places above a thousand are not covered.
- Integers (`WALKS`, one line of data per type): a walk drawn from the type's own numbers, kept only when it ends on the
  answer; the way (left or right) is chosen before the point moves.
- Place value (`places@1`, an aid that is a way of answering): a number asked for in figures is written into its seats
  (crore, lakh, thousand, ones); it cannot be checked until every seat has its digit. Fades to the plain box.

`one-help@1`: "I'm stuck" and "Work it out step by step" are one place. Being stuck (or "Help me with the next step"
inside the working) opens the working with the next step asked there, a box to fill; a step the child cannot do is
shown by "Help: show me this step", and the next one loads. The child's own free lines are for working alone and are
not help; asking for a step is recorded as help, as before. Questions with no working panel keep the old button.

`prep@1` (`packages/learning/src/prep.ts`): "before you answer". The one thing a group's documented mistake skips is
asked in its own boxes before the answer box appears: an estimate rounds each number first ("12 is about ▢"); a length,
time or money amount in two units changes the bigger unit first ("1 m = ▢ cm", "So 8 m = ▢ cm"). A wrong entry gets a
question, a second one the fact. Read from the question's words by rule, kept only when the prep's arithmetic gives the
verified answer, never holding the answer. An aid: it fades to the plain box and is never in a test. 13 types so far.

`one-page-story@1`: in the one-part-per-screen lesson (Classes 1 to 5) the opening story is a few lines, so it is shown
above the guess it asks for instead of on a page of its own (one Next fewer; no going Back to read the question).

`where-used@1` (`packages/learning/src/uses.ts`, `WhereUsed.tsx`): under a lesson, an optional "Where is this used?"
button: one everyday place the skill lives (two short lines) and one playful question. Never shown unless asked for,
nothing recorded, not in practice or tests. Written once per skill as data; a skill with no honest everyday use has no
entry. 42 of the 62 Class 5 skills so far. No pictures yet.

`where-used@2`: our own drawings (plain SVG in the page's ink, no photographs) for eight entries so far (leaning tower,
photo as a matrix, dosa, fence, tiles, ball, 3-4-5 corner, temple tower), and entries for the other classes: 99 skills of
345 in all, including matrices, determinants, derivatives, integrals, trigonometry, logarithms and probability.
