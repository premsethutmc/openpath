# The hosted server for a real learner (family-pilot@1)

The demo's device mode (DEVICE_MODE.md) keeps a record in one browser. A real learner needs the record kept: on a server,
in a database, reachable from any device, and readable (with the parent's permission) to improve the product. The server
already existed and is tested (accounts, learners, records, server-side grading); what was missing was somewhere to run it
with a database that lasts.

## What it is

One private site, one origin:

- the site password first (nothing is served before it), as on the demo;
- then OpenPath's own parent account (email and password), and the learners under it;
- the welcome screen with the English and Maths tiles; a learner can be added from either;
- records in the owner's own PostgreSQL database (Neon's free plan), reached only over an encrypted connection.

Files: `deploy/pilot/Dockerfile`, `deploy/pilot/start.sh`, `backend/config/pilot.py`, `render.pilot.yaml`. It is the preview
deployment (`deploy/preview`, synthetic data only) with one difference that matters: the preview ignores `DATABASE_URL` and
falls back to a throw-away file; the pilot refuses to start without its PostgreSQL database, so a real record can never land
in a file the next deploy discards.

## Setting it up (owner)

1. Neon: create a free project (region Singapore), copy its connection string.
2. Render: the service `openpath-family` (free, Docker, Singapore, branch `main`, deploys only when asked). In its
   Environment set `DATABASE_URL` to the Neon string and `DEMO_PASSWORD` to a site password of your choosing. The two secrets
   (`DEMO_SESSION_SECRET`, `DJANGO_SECRET_KEY`) are generated by Render.
3. Deploy. `start.sh` applies the database migrations, checks the settings and the grader bundle, then starts.
4. Open the site, enter the site password, choose English, create the parent account, then open Maths and add the learner.

Neither the connection string nor the passwords are committed, logged, or sent through chat.

## What to expect

| | |
|---|---|
| First visit after a quiet spell | Slow: a free Render service sleeps after about 15 minutes without visitors and takes about a minute to wake; a Neon database also wakes on first use |
| Progress | Kept in the database; the same on any device after signing in |
| Grading | The server's recorded decision is what is shown (mode `shadow`, as approved for the preview) |
| Forgotten account password | There is no mail service, so no reset link can be sent. Keep the password safe; it can be reset by hand in the database if needed |
| Backups | Neon's free plan is not a backup. The parent can export a learner's record (Me → export in English; `/api/pupils/<id>/export/`). A scheduled backup is not built |
| Who can read a record | The parent. A developer only if the parent turns on sharing for diagnostics for that learner (every look is logged) |
| Written answers | Saved; marked only by an educator account, which the pilot does not have yet |

- By hand, in a headless browser against the same one-origin server pair (the gate server and Django) with a test database:

- NOT checked here: the Docker image build and the connection to Neon. This environment has no Docker daemon and no database

## Before a child uses it

- The owner holds the parent account and decides what name is shown (a first name or nickname is enough).
- This is an early version: lessons and questions are machine-checked, not reviewed by a teacher.
- Free plans change. If Render or Neon change theirs, the record should be exported first.

## Signing in once (one-account@1)

- Maths has its own "Create an account" on its sign-in screen; a parent is never sent to another app to register.
- A parent's sign-in lasts 180 days on a device; the site password is asked once a year per device.

## For parents (parent-view@1) and keeping progress safe (keep-safe@1)

- "For parents" on the Maths home: questions this week, right at the first try, days worked, lessons opened, a bar for
  each of the last seven days, and the skills worked on in the last 14 days grouped as could use your help / going
  well / also worked on. All are counts from the learner's record; nothing is estimated.
- A name-only learner's parent can add an email and password there ("Keep this progress safe"). The same records then
  open on any device, and the browser's own key is removed. There is no reset-by-email on this site yet.
- An email account's parent can download a copy of the learner's record from the same page.

## Timing and the competency profile (timing@1, competency-profile@1)

- Each answer now carries about how long the question was on screen (`ms`; the clock stops while the page is hidden, and
  more than ten minutes is treated as a pause and not kept). It is never part of how an answer counts.
- The parents' page has Week / Month / Year. For each topic it shows questions, right at the first try, answered without
  help, and pace; and four findings: quickest, most accurate, most practised, stuck on.
- Measures, not predictions: "quicker" compares the learner with their own usual pace (the middle of their topic paces),
  never with other children; a measure appears only after five answers. Timing exists only from 13 Nov 2026.

## Opening at once (instant-open@1) and staying in (stay-in@1)

- The Maths page carries its own first screen (plain HTML and CSS), so something is on screen before any script runs.
- The family image builds Maths with `--shell-cache`: a service worker at `/year/sw.js` keeps the app's own files on the
  phone, answers from that copy at once (also while the server is asleep), and fetches newer files for next time. It
  never handles `/api/` or anything outside `/year/`. If a newer app arrives while the old one is starting and nothing
  has been touched, the page reloads itself once.
- While the server cannot be reached the opening screen stays, says the first open can take up to a minute, and asks
  again every three seconds for two minutes. If the site password has run out, the visitor is sent to the password page.
- The site password's sessions now survive a restart (the salt comes from the session secret). Before, every restart,
  and so every wake from sleep, asked for the site password again.

## Question wording (kid-say@1)

In the child build every generated question is shown as one short ask (`packages/learning/src/kid-say.ts`). Only the
wording and the answer box change; the question, its answer and the marking do not. Rules: one ask, with typing rules
moved into the box (₹ before it, a unit after it, separate m and cm boxes, numbers to tap into order, a letter to
tap); a picture only where the maths is visual, and the sentence never does the picture's work; a calculation stays a
calculation. About 50 of the wordiest Class 5 families have their own rewrite; the rest follow the general rules.
`kid-say.test.ts` checks every Class 5 family: no typing instructions left, no number that the question did not give,
and every tap, order and two-box answer rebuilds an answer the existing marking accepts. Test and review builds keep
the full wording.

## Speed of saves (grader-serve@1, 16 Nov 2026)

- **The grader is kept running.** Checking one answer used to start a program and read the whole 15 MB grader each time
  (about 0.8 s on a development machine, more on the free server). The same bundle is now started once with `--serve` and
  asked one line at a time: about 1 ms an answer after the first. The decisions come from the same code; a test holds the
  kept grader's replies against one-shot runs. Any trouble (no reply in time, an unexpected reply, a dead process) falls back
  to a one-shot run. It is stopped after 1200 quiet seconds (`OPENPATH_GRADER_IDLE`; 120 at first, which stopped it during any lesson longer than
  two minutes, so the next answer paid the start again: 13 s measured on the family site on 16 Nov 2026, against 25 to 77 ms
  for the answers after it). grader-warm@1 starts it in the background when a learner's mathematics is opened, so the start
  is spent while a lesson is read; a grader just started is allowed `OPENPATH_GRADER_START` seconds (30). It is and restarted every 300 answers
  (`OPENPATH_GRADER_RECYCLE`). It holds about 300 MB while it runs, the same as one one-shot run at its peak, and the two
  are never in memory together. `OPENPATH_GRADER_SERVE=off` returns to a one-shot run for every answer.
- **Database connections are reused** for up to a minute and checked before each request (`CONN_MAX_AGE = 60`,
  `CONN_HEALTH_CHECKS`), so the saves of one sitting do not each open a new encrypted connection.
- Not measured on the live server (the free plan gives no timings). Open: the size of the app itself (14.8 MB of code,
  2.9 MB to download) and the server's small processor.

## The first answer after opening (grader-warm@1, 17 Nov 2026)

Measured on the family site: the first answer after the grader has stopped takes 10 to 13 s (the grader starting on 0.15 of
a CPU); later ones 25 to 130 ms. The grader is now started in the background when a learner's mathematics ledger is read (at
most once in five minutes), so the start is spent while the lesson is read. Only that warm-up, which asks nothing, gives a
fresh grader longer to start (`OPENPATH_GRADER_START`, 30 s). An earlier version gave every fresh start that time: a slow
working check then held an answer for half a minute, and the Grade 10/12 browser journey timed out four times running.

## An answer that cannot be read (ask-first@1, 17 Nov 2026)

On the family site the owner wrote two answers the checker could not read, eight seconds apart, and the skill was paused for
two days with "this needs a person" (pause@1 counts unreadable answers that were sent; the checker reads a bare number, so
"7 birds", "seven" and "9-2" are all unreadable). In the child build an answer the app's own preview cannot read is no
longer sent: the child is shown how to write it ("Type just your final answer, for example 7") and tries again at once.
Nothing is recorded, so this can no longer pause a skill. Other builds are unchanged: the first unreadable answer is
recorded and asked about, as before.

plain-answer@1: "7 birds" for "How many birds…?" is read as 7 (`packages/learning/src/plain-answer.ts`): only when the answer is a
whole number and every word after it is a thing the question names; never a unit ("7 cm"), never another word.

Open: "seven" and "9-2"; whether pause@1 should ever apply to unreadable answers.


## Teaching dashboard (teaching-review@1)

`/review/#teaching` lists every story lesson and help card, by class (Class 5 first), as the child sees it: a lesson
can be played there. Each shows where it came from (written by hand, or made by rule from the skill's lesson) and is
approved, rejected or sent back in one step by an account with the educator role (`manage.py content_reviewer grant
<email> --role educator`). A decision applies to the version shown: when the lesson or card changes it returns to "To
review". Decisions are a record only; they do not yet hide anything from learners. The items and their hashes are in
`content/learning/teaching.v1.json` (generated: `node tools/regen.mjs`).

## Words and picture agree (picture-words@1)

Where a question's words point at a picture ("the number cards in the picture") and the family draws a row of things
as a table with no real headings, the row is drawn as cards (`pictured` in `family-kit.ts`, `as: "tiles"` in
`Figure.tsx`), in the question and in its lesson. A table with real headings (a bill, a price list) stays a table.
`frontend/src/year/picture-words.test.ts` checks every family: words that point at a picture have one, and cards are
never drawn as a table of data.

The owner reviews teaching without a database grant when their account's email is in `OPENPATH_OWNER_EMAILS`.
