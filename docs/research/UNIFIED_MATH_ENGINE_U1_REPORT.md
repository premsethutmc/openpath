# Unified Mathematics Engine U1

## Decision

**REVISE.** U1 provides one operational assessment API for arithmetic, algebra,
structured Euclidean geometry, and one bounded mixed geometry/algebra handoff.
The tested contract preserves truth, justification, completeness, unsupported
reasoning, proof dependencies, and first-invalid-step information. It is not yet
a general cross-domain theorem system: mixed reasoning is currently limited to
the typed triangle-angle-sum handoff, and geometry is invoked through a local
Python subprocess rather than a production service or native package boundary.

## Architecture and integration paths

The public TypeScript entry point is:

```ts
assessMathematicalWorking(problem, studentWorking, options)
```

It returns `openpath-unified-math-assessment@1`, a shared envelope containing a
domain-specific payload rather than forcing geometry into algebra's data model.

| Domain | Dispatch path | Existing authority reused |
| --- | --- | --- |
| Arithmetic | unified API → `assessWorking` | math-core number reasoner |
| Algebra | unified API → `assessWorking` | math-core symbolic, equation, and multivariate reasoners |
| Geometry | unified API → JSON adapter → `verify_submitted_proof` | G4 geometry reasoner and proof graph |
| Mixed | geometry verification → typed handoff → `assessWorking` | both engines, with separate provenance |

The geometry adapter is exposed as a JSON stdin/stdout command by
`geometry_reasoner.unified_api`. A geometry adapter failure is contained and
returns `unsupported`; a following math-core request remains usable.

## Shared contract

The envelope distinguishes `verified`, `invalid`, `incomplete`,
`missing-assumption`, `unsupported`, `contradictory`, `resource-exhausted`,
`malformed`, and `ambiguous`. It preserves:

- zero-based first invalid step, where identifiable;
- per-step justification and originating reasoner;
- proof and mathematical dependencies;
- domain restrictions and outstanding obligations;
- completion independently from correctness;
- skill evidence;
- native domain payloads and reasoner/contract versions.

Geometry's native `unknown`/unsupported verdict is never converted to invalid.
Malformed and exhausted work never receives a guessed mathematical verdict.

## Cross-domain handoff

U1 supports a typed `triangle-angle-sum` obligation. For known angles 65° and
45°, geometry must first justify `A + B + C = 180°`. Only then does the adapter
submit `x + 65 + 45 = 180` to math-core. Both of these valid routes pass:

- `x = 180 - 65 - 45`, then `x = 70`;
- `x + 110 = 180`, then `x = 70`.

A numerically correct `70` is not assessed when the triangle is degenerate or
the geometric premise lacks its required nondegeneracy assumption. Conversely,
a justified angle-sum theorem does not hide an invalid calculation.

## Independent U1 validation

`independent-cases.v1.json` contains 200 explicitly labelled cases, 50 per
domain. Expected labels are authored from arithmetic formulas and theorem
preconditions, not generated by the engine. The cases include correct and
alternative routes, invalid transformations, incomplete proofs, missing
assumptions, contradictory premises, unsupported operations, malformed input,
and resource exhaustion.

| Domain | Cases | Contract mismatches | Mean elapsed |
| --- | ---: | ---: | ---: |
| Arithmetic | 50 | 0 | 0.407 ms |
| Algebra | 50 | 0 | 1.344 ms |
| Geometry | 50 | 0 | 46.736 ms |
| Mixed | 50 | 0 | 50.579 ms |

- False acceptances: **0**
- False rejections: **0**
- First-invalid-step matches: **200/200** (including expected `null`)
- These are bounded fixture results, not claims of universal mathematical
  coverage.

Additional adversarial tests cover malformed working, a deeply oversized
expression, geometry budget exhaustion, unavailable geometry runtime isolation,
and recovery of an independent arithmetic request.

## Resource safety

Math-core retains its existing character, line, computation, and derivation
budgets. Geometry receives a bounded rule-application budget, runs with a
five-second process timeout and a two-megabyte output limit, and fails closed.
The unified layer does not share mutable assessment state between reasoners.

The 200-case evaluation took approximately 4.95 seconds in this cloud runner;
geometry process startup dominates the geometry and mixed means. These numbers
are reproducibility measurements, not production latency targets.

## Supported boundary and remaining work

Implemented:

- Existing math-core arithmetic, equations, symbolic, and multivariate routes.
- Structured geometry proofs covered by the G4 theorem language.
- Proof dependencies, incomplete/unsupported outcomes, and first-invalid-step.
- A typed triangle-angle-sum bridge from geometry into algebra.

Unsupported or incomplete:

- Natural-language geometry proofs and diagram/image interpretation.
- Arbitrary cross-domain proof obligations beyond triangle angle sums.
- A browser-safe or deployed geometry runtime; U1 currently requires Python and
  Node subprocess support.
- Arbitrary calculus, trigonometry, matrices, and free-form proof languages not
  already supported by math-core or G4 geometry.
- General inference from contradictory premises (the result remains explicitly
  contradictory and no explosion is allowed).

Before merge, replace or formally package the subprocess boundary, add typed
handoff kinds only for independently defined mathematical obligations, and run
the same corpus in the intended production runtime. The underlying engines and
their mathematical semantics should remain unchanged.
